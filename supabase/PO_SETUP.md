# ระบบ PO / รับสินค้า สำเพ็ง

เส้นทาง: /admin/purchase-orders

## ตั้งค่าฐานข้อมูล (ต้องทำก่อนใช้งาน)
1. รัน supabase/migrations/202610080001_add_item_stock_quantity.sql ใน Supabase SQL Editor หากยังไม่ได้รัน
2. ถ้ายังไม่เคยตั้งค่าระบบ PO ให้รัน supabase/migrations/202610080002_purchase_orders.sql
3. ถ้าเคยรัน SQL รุ่นที่ต้องล็อกอินแล้ว ให้รัน supabase/migrations/202610080003_po_without_login.sql เพื่อปรับสิทธิ์โดยเก็บข้อมูลเดิม
4. เปิดแท็บ PO / รับสินค้าได้เลย ไม่ต้องสร้างบัญชีหรือเข้าสู่ระบบ
5. ระบุยอดคงเหลือจริงในหน้าคลังก่อนรับสินค้า หากยังไม่เคยนับระบบจะไม่ถือว่า NULL เป็น 0

ตามที่ผู้ใช้ยืนยัน ระบบใช้งานภายในโดยไม่ล็อกอิน ผู้เข้าถึงเว็บสามารถอ่าน สร้าง PO และรับของเพื่อเพิ่มคลังได้
ตาราง PO และประวัติให้แอปอ่านได้ แต่ไม่ให้ INSERT/UPDATE/DELETE โดยตรง
การสร้าง PO และรับสินค้าทำผ่าน RPC ที่ตรวจข้อมูล ล็อกยอด และป้องกันคำขอซ้ำ
ผู้ทำรายการกรอกชื่อผู้บันทึกและชื่อผู้รับ ไม่ผูกกับบัญชีที่ยืนยันตัวตน

## กรอกเอง
- กดสร้าง / นำเข้า PO กรอกเลข PO แหล่งที่มา วันที่ และชื่อผู้บันทึก
- เพิ่มรายการ เลือกสินค้าในคลัง จำนวน หน่วยรับ ตัวคูณหน่วย และมูลค่าต่อหน่วยต่อหน่วยรับ
- ตรวจยอดรวมและบันทึก PO ยังไม่เพิ่มยอดคลัง

## นำเข้าจาก Excel
- ดาวน์โหลดไฟล์ตัวอย่างจากหน้า PO หรือใช้ .xlsx/.xls/.csv ชีตแรก ขนาดไม่เกิน 5 MB ไม่เกิน 500 รายการ
- 1 ไฟล์ต่อ 1 PO กรอกข้อมูลหัว PO ในเว็บ
- คอลัมน์บังคับ: รหัสสินค้า, จำนวน, มูลค่าต่อหน่วย
- คอลัมน์เพิ่มเติม: หน่วยรับ, ตัวคูณหน่วย
- รองรับชื่อคอลัมน์อังกฤษ product_code, quantity, unit_price, purchase_unit, units_per_pack
- เก็บรหัสสินค้าที่มีเลขศูนย์นำหน้าเป็นข้อความใน Excel
- หากรหัสไม่พบหรือซ้ำในคลัง ให้จับคู่เองก่อนบันทึก ไม่มีการสร้างสินค้าใหม่อัตโนมัติ
- ไม่มีการนำเข้าเลข PO แหล่งที่มาหรือข้อมูลหัว PO จากไฟล์ในรุ่นนี้
- จำนวนต้องเป็นจำนวนเต็ม ราคามีทศนิยมไม่เกิน 2 ตำแหน่ง สินค้าซ้ำใน PO ต้องรวมไว้ในแถวเดียว

## รับสินค้า
- เปิด PO กรอกจำนวนที่มาจริงแต่ละรายการ (ตามหน่วยรับ) และชื่อผู้รับ
- กรอก 0 หรือเว้นช่องหากยังไม่ได้รับรายการนั้น รับบางส่วนหลายครั้งได้
- รับเกินยอดค้างรับไม่ได้
- ตัวคูณหน่วยใช้แปลงเป็นหน่วยคลัง เช่น รับ 2 กล่อง ตัวคูณ 12 เพิ่มคลัง 24 ชิ้น
- ยืนยันรับสินค้าแล้วจะเพิ่มสต็อกและบันทึกประวัติใน transaction เดียว
- PO เปลี่ยนเป็นรับบางส่วนหรือรับครบโดยอัตโนมัติ
- มูลค่าต่อหน่วย PO ไม่เปลี่ยนราคาสินค้าในใบเบิก
- มี request_id ป้องกันส่งซ้ำ บล็อกยอดรับเกิน และล็อก PO/สินค้าเมื่อรับพร้อมกัน
- ประวัติเก็บชื่อผู้บันทึกและผู้รับที่กรอก
- รุ่นนี้ไม่มีการยกเลิก PO หรือย้อนยอดรับ และยังไม่หักคลังอัตโนมัติจากใบเบิก
