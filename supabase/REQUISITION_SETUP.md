## เปลี่ยนรหัสแผนก
รันใน SQL Editor ด้วยสิทธิ์เจ้าของฐานข้อมูลเท่านั้น (เว็บและ anon ไม่มีสิทธิ์อ่านหรือเปลี่ยนรหัส):

~~~sql
select public.set_department_code(
 (select id from public.branches where name='ชื่อแผนก'),
 'รหัสใหม่ความยาวอย่างน้อย12ตัว'
);
~~~

รหัสต้องยาว 12–100 ตัวและไม่ซ้ำแผนกอื่น เปลี่ยนแล้ว session เดิมของแผนกนั้นถูกยกเลิกทันที หากลืมรหัสให้ตั้งใหม่ เพราะฐานข้อมูลเก็บเฉพาะ hash
เมื่อเพิ่มแผนกใหม่ รัน CREATE_DEPARTMENT_CODES.sql อีกครั้ง จะสร้างให้เฉพาะแผนกที่ยังไม่มีรหัส

## พฤติกรรม
- สินค้าแสดงสีปกติและเบิกได้แม้คงเหลือ 0 หรือจำนวนเบิกมากกว่าคลัง ไม่มีการตัดคลังอัตโนมัติเพิ่มจากงานนี้
- หมายเหตุใบเบิกและหมายเหตุผู้ตรวจสอบแยกกัน สูงสุดช่องละ 2,000 ตัว
- อนุมัติบางรายการ ตัดออกและคืนรายการก่อนกดยืนยันได้ เก็บรายการที่ขอเดิมกับผลอนุมัติในประวัติ ไม่ลบหลักฐานรายการที่ตัด
- ประวัติแผนกกรองชื่อผู้เบิก โซน วันที่ สถานะได้; แอดมินดูทุกแผนกผ่าน รายงาน > ประวัติการเบิก
- แก้รายการ จำนวน ผู้เบิก โซน ผู้ส่ง และหมายเหตุได้เฉพาะรออนุมัติ ป้องกันชนกันด้วย version และ row lock; หากข้อมูลเปลี่ยนต้องโหลดใหม่
- อนุมัติ/ปฏิเสธแล้วล็อกใบ ไม่เปิดให้กลับเป็นรออนุมัติ
- หากไม่เลือกจดจำ session หมดอายุ 12 ชั่วโมงและเก็บเฉพาะแท็บ หากเลือกจดจำจะไม่จำกัดวัน ล็อกเอาต์แล้วใช้ token เดิมไม่ได้
- ใบเบิกเดิมผูกแผนกด้วยชื่อที่ตรงและไม่ซ้ำ ใบที่จับคู่ไม่ได้ยังอยู่ในประวัติแอดมิน ต้องตรวจชื่อก่อนแก้ branch_id ใน SQL
- เก็บประวัติก่อน/หลังใน requisition_changes; requested_items เป็น snapshot ก่อนแอดมินตรวจสอบ

## ขอบเขตสิทธิ์หลังปรับ
หน้าเว็บหลังบ้านตรวจ session ของสต็อกหรือแอดมินกลางก่อนแสดงหน้า การเปลี่ยนรหัสและการเลือกแผนกตรวจสิทธิ์ในฐานข้อมูลด้วย ส่วนสิทธิ์อ่านตาราง/ฟังก์ชันธุรกรรมเดิมของหลังบ้านยังเป็นระบบภายในแบบเดิม การปิด API หลังบ้านทั้งหมดจากผู้ใช้ทั่วไปต้องปรับ RLS และฟังก์ชันคลัง/PO/รายงานร่วมกัน ไม่ใช่เพียงปิดหน้าเว็บ

## จดจำการเข้าใช้งานแบบไม่จำกัดวัน
รัน migrations/202610280004_remember_department_login.sql หลัง migration หลัก จากนั้นเลือก จดจำการเข้าใช้งานบนเครื่องนี้ ตอนเข้าใช้งานครั้งถัดไป
ระบบเก็บ session token ใน localStorage ไม่เก็บรหัสผ่านจริง ปิดแท็บหรือเบราว์เซอร์แล้วเปิดใหม่ได้โดยไม่ต้องพิมพ์รหัส และซิงก์การเปลี่ยนบัญชีหรือออกจากระบบระหว่างแท็บ
Session ที่เลือกจดจำไม่จำกัดวัน (expires_at เป็น infinity) ยังยกเลิกได้ด้วยการออกจากระบบหรือเปลี่ยนรหัสของแผนก/แอดมินกลาง การล้างข้อมูลเบราว์เซอร์ทำให้ต้องกรอกรหัสใหม่ หากไม่เลือกจดจำจะใช้เฉพาะแท็บและหมดอายุ 12 ชั่วโมงตามเดิม

## ดูรหัสทุกแผนกจากหลังบ้าน
รัน migrations/202610290001_view_department_codes.sql หลัง migration บทบาทสต็อก/แอดมินกลาง จากนั้นไป แผนก / โซน > ดูรหัสทุกแผนก สามารถค้นหา แสดง/ซ่อน คัดลอก และกดเปลี่ยนรหัสได้
ฟังก์ชันตรวจ session ที่ยังใช้ได้และบทบาทจากฐานข้อมูลทุกครั้ง เฉพาะแอดมินกลางและแผนกสต็อกเท่านั้นที่ดูรหัสได้ ไม่แสดงรหัสแอดมินกลางในรายการนี้
รหัสใหม่เก็บทั้ง hash สำหรับเข้าใช้งานและค่าที่เข้ารหัส AES-256 สำหรับการดูผ่านผู้ดูแล กุญแจเข้ารหัสเก็บในตาราง private ที่ anon/authenticated อ่านตรงไม่ได้
รหัสเดิมที่มีแต่ hash ย้อนคืนไม่ได้ ระบบไม่เปลี่ยนรหัสเดิมให้อัตโนมัติ เมื่อแผนกนั้นเข้าใช้ด้วยรหัสที่ถูกต้องอีกครั้ง ระบบจะเก็บสำเนาเข้ารหัสเพื่อให้ผู้ดูแลดูได้ หรือผู้ดูแลตั้งรหัสใหม่จากหน้าจอได้
การเปิดหน้าดูรหัสไม่บันทึกรหัสลง localStorage ไม่ export รหัสเป็นไฟล์ และปิดหน้าต่างแล้วล้างรายการออกจากหน่วยความจำของ component
